# 疑难解答（Troubleshooting）

> 遇到问题先来这里找，找不到再问群里。

## 🛠 编译问题

### Q: CMake 配置失败：`Could not find Qt6`

**原因**：CMake 找不到 Qt 6 的安装路径。

**解决**：
```bash
# 方法 1：命令行指定路径
cmake -B build -S . -DCMAKE_PREFIX_PATH=/path/to/Qt/6.6.0/gcc_64

# 方法 2：设置环境变量
export Qt6_DIR=/path/to/Qt/6.6.0/gcc_64/lib/cmake/Qt6

# 方法 3：在 Qt Creator 中直接打开 CMakeLists.txt，它会自动用配置好的 Kit
```

常见 Qt 安装路径：
- **Windows**：`C:\Qt\6.6.0\mingw_64` 或 `C:\Qt\6.6.0\msvc2019_64`
- **macOS**：`/Users/<user>/Qt/6.6.0/macos`
- **Linux**：`/opt/Qt/6.6.0/gcc_64`

### Q: 编译报错 `undefined reference to vtable for SomeClass`

**原因**：你给一个含 `Q_OBJECT` 宏的类添加了文件，但 CMake 没收录。

**解决**：
1. 检查 `CMakeLists.txt` 的 `PROJECT_SOURCES` 是否包含你的新 `.h/.cpp`
2. **完全删除 build 目录**：`rm -rf build/`
3. 重新配置：`cmake -B build -S .`
4. 重新编译：`cmake --build build`

### Q: 编译报错 `'QApplication': No such file or directory`

**原因**：找到的是 Qt5 而非 Qt6，或者 Widgets 模块未链接。

**解决**：
1. 确认 `find_package(Qt6 ...)` 行存在
2. 确认 `target_link_libraries` 包含 `Qt6::Widgets`
3. 删除 build 目录重新配置

### Q: Windows 下中文乱码（输出和源码）

**解决**：MSVC 默认非 UTF-8。我们在 CMakeLists 中加了 `/utf-8`，但你需要确保源文件本身存的是 UTF-8 编码：

- Qt Creator：工具 → 选项 → 文本编辑器 → 行为 → 默认编码 = UTF-8
- VSCode：右下角点 "UTF-8" → "通过编码保存"

## 🐛 运行时问题

### Q: 启动后立刻闪退，没有报错

**排查步骤**：
1. **从命令行启动**，看输出：
   ```bash
   cd build
   ./StudyAdventure          # Linux/macOS
   StudyAdventure.exe        # Windows
   ```
2. 看 `qDebug()` 的输出，找到崩溃前的最后一条
3. 如果输出为空，可能是 main 函数里就崩了，用调试器（Qt Creator 的 🐞）打断点

### Q: 资源文件加载不到（图片/JSON 没显示）

**原因**：资源路径写错了。

**Qt 资源路径规则**：
- 资源系统打包：`":/scripts/week1.json"`（前缀 `:/`）
- 文件系统路径：`"assets/scripts/week1.json"`（相对路径，相对于运行目录）

**调试**：在 main.cpp 加一行
```cpp
qDebug() << "Working dir:" << QDir::currentPath();
qDebug() << "Resource files:" << QDir(":/").entryList();
```

### Q: 信号槽连接成功但槽函数没被调用

**常见原因**：
1. **没继承 QObject**：宿主类必须派生自 QObject 且有 `Q_OBJECT` 宏
2. **槽函数签名不匹配**：参数类型、数量、const 必须完全一致
3. **没添加 .h 到 CMakeLists**：MOC 处理不到，信号槽元数据缺失

**调试**：
```cpp
bool ok = connect(sender, &SenderClass::someSignal,
                  receiver, &ReceiverClass::someSlot);
qDebug() << "Connect result:" << ok;  // 应该是 true
```

## 🔀 Git 问题

### Q: `git pull` 报 merge 冲突怎么办

```
CONFLICT (content): Merge conflict in src/xxx.cpp
```

**步骤**：
1. 打开冲突文件，找到
   ```
   <<<<<<< HEAD
   你的版本
   =======
   他的版本
   >>>>>>> origin/develop
   ```
2. 手动改成你想要的内容，删除三行标记
3. `git add src/xxx.cpp`
4. `git commit`（继续合并）

**完全搞不定**：
```bash
# 放弃合并，回到合并前的状态
git merge --abort

# 然后问群里，看队友能否帮你
```

### Q: 不小心改了不属于自己模块的文件

**应对**：
```bash
# 如果还没提交：撤销那个文件的修改
git checkout -- src/story/xxx.cpp

# 如果已经提交了但没推送：
git reset HEAD~1 -- src/story/xxx.cpp  # 把这个文件移出最后一次提交
git checkout -- src/story/xxx.cpp       # 恢复内容

# 已经推送了：找队友 review 时说明情况，让他确认是否回退
```

### Q: 提交了不该提交的文件（比如 build/ 目录）

```bash
# 从 git 跟踪中移除（但保留磁盘文件）
git rm -r --cached build/
git commit -m "[git] 移除 build 目录"
git push

# 确认 .gitignore 里有这一项，下次就不会再加入
```

## 💡 Qt 相关常见坑

### 1. `QObject::connect: No such signal`

**症状**：编译能过，运行时报错说找不到信号。

**原因**：用了旧式字符串语法 `SIGNAL(xxx())` 但拼错或参数不对。

**修复**：用新式语法，编译期就会报错：
```cpp
// ❌ 旧式（容易拼错）
connect(btn, SIGNAL(clicked()), this, SLOT(onClick()));

// ✅ 新式
connect(btn, &QPushButton::clicked, this, &MyClass::onClick);
```

### 2. Lambda 捕获 this 后 this 已被销毁

**症状**：界面切换后崩溃。

**原因**：
```cpp
QTimer::singleShot(1000, [this]() {
    this->doSomething();   // 1 秒后 this 可能已被销毁！
});
```

**修复**：用 connect 形式，把上下文 QObject 传进去：
```cpp
QTimer::singleShot(1000, this, [this]() {
    this->doSomething();   // this 销毁时 connection 自动断开
});
```

### 3. 同名 enum 和 class 冲突

**症状**：编译报错说类型不匹配或找不到方法。

**例子**：我们项目里曾经把地图热区类命名为 `Location`，与 `SA::Location` 枚举重名导致编译失败。

**修复**：类名加后缀，比如 `LocationItem`、`SubjectButton` 等。
