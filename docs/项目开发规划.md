## 三、三人分工原则与模块边界

本项目的核心分工设计思想是 **"**垂直切片 + 接口约定**"**：将系统按业务功能纵向划分为三个相对独立的子系统，每人负责一个子系统从底到顶的全部实现，通过事先约定好的基类接口和 JSON 文件格式进行交互。这样三人在阶段三可以做到 **10 天内零阻塞并行开发**。

| **维度** | **成员 A · 剧情核心** | **成员 B · 界面核心** | **成员 C · 玩法核心** |
| --- | --- | --- | --- |
| **主要负责类** | **StoryEngine**、**DialogWindow**、**EndingJudge** | **QMainWindow**、**MapScene**、状态栏组件 | **MiniGame**及 6 个派生类、**Player**、**SaveManager**、**GameManager** |
| **文件归属** | src/story/、assets/scripts/ | src/ui/、src/map/、assets/images/ | src/games/、src/core/、assets/data/ |
| **输入依赖** | Player 提供数值读取接口、MiniGame 提供启动接口 | StoryEngine 提供当前剧情节点信息、GameManager 提供状态 | 基类接口（来自共同设计，5/14 前定死） |
| **输出产品** | 剧情节点切换信号、数值变更指令 | UI 交互事件信号 | 游戏结果信号、数值修改服务、存档接口 |
| **代码量预估** | 约 600 行 C++ + 800 行 JSON | 约 700 行 C++ + 资源整理 | 约 1000 行 C++（6 个游戏分担） |
| **解耦机制** | 通过 QJsonObject 传递剧情数据，不直接调用 UI 类 | 通过 **Qt 信号槽 **响应业务事件，UI 不持有业务对象 | 通过 **MiniGame 基类指针 **回传结果，主程序无须知道具体游戏 |

**关键约定（必须遵守）：**

- **1. 谁定义的类，谁拥有它**——其他人只能通过 public 接口使用，不能修改实现细节。

- **2. 跨模块通信只走信号槽和 JSON**——避免 #include 别人的内部头文件，避免编译期耦合。

- **3. 各人的 src/ 子目录互不写入**——只读他人模块的公开头文件，不修改任何源文件，违反则触发代码冲突。

- **4. 公共头文件（基类、enum、常量）放在 src/common/**——修改需在群里同步，并立刻 push 上 develop 分支。

## 五、协作机制


## 5. 1  Git 分支策略

采用简化版的 GitFlow，针对 3 人 20 天小项目优化，避免过度复杂：

| **分支** | **用途** | **规则** |
| --- | --- | --- |
| **main** | 稳定版本 | 仅在阶段性里程碑合入（5/17 框架完成、5/27 编码完成、5/30 测试完成、6/06 最终版本）。其余时间禁止直接推送，必须通过 Pull Request 合并。 |
| **develop** | 集成分支 | 默认开发分支，所有 feature 完成后合入此分支。每日至少同步一次个人 feature 到 develop。每周三、周六晚由队长触发集成测试。 |
| **feature/story-*** | A 的分支 | 成员 A 的所有功能分支前缀。如 feature/story-engine、feature/story-week1。一个 feature 完成且自测通过后合入 develop。 |
| **feature/ui-*** | B 的分支 | 如 feature/ui-map、feature/ui-mainwindow。 |
| **feature/game-*** | C 的分支 | 如 feature/game-minesweeper、feature/game-tictactoe。 |
| **hotfix/*** | 紧急修复 | 仅在集成测试期间使用。修复后直接合入 develop 与 main。 |


### Git 操作规范

- **Commit 信息：**使用 [模块] 动作简述 格式。例如 [story] 实现分支跳转逻辑、[ui] 修复地图点击响应bug。

- **Pull Request：**向 develop 合入时，必须 @ 另一位成员 review，至少 1 个 approval 才能合入。

- **拉取频率：**每天开工前执行 git pull origin develop，避免落后太多导致 merge 灾难。

- **禁止：**直接推到 main、强制推送（force push）、推送大型二进制文件（用 Git LFS 或链接）。

## 5. 3  文档同步机制

- **代码注释**：所有 public 接口必须有 Doxygen 风格注释；JSON 剧本格式在 docs/script_format.md 中维护。

- **共享白板**：使用 **腾讯文档/飞书文档** 维护一份实时更新的 "接口约定表"，列出所有跨模块接口的签名、参数含义。任何接口变更必须先改文档后改代码。

- **GitHub Issues**：用 Issue 跟踪所有 bug 和待办；用 Label 区分 [story] [ui] [game] [bug] [enhancement]；分配 Assignee 明确负责人。

- **作业报告**：在腾讯文档协作编写，最后用 LaTeX 或 Word 排版为 PDF。
