# 学海漫游：异世界的信科少女 —— 作业报告

**成员 A · 第 1-3 章（功能介绍 / 剧情系统设计 / 五种结局）**

---

## 第 1 章 · 功能介绍

### 1.1 项目定位

《学海漫游：异世界的信科少女》是一款以**北大信科大一课程**为背景的乙女向养成模拟游戏。玩家扮演大一女生，因期末通宵晕倒穿越至异世界，与四门拟人化课程（**程序设计、高等数学、线性代数、人工智能引论**）共度一学期。通过 5 周的剧情推进、自由探索、6 个知识小游戏，玩家管理三组核心数值（好感度 ×4 / 压力 / 线代黑化），最终触发 5 种迥异的结局。

### 1.2 核心玩法循环

```
        ┌────────────┐    剧情节点     ┌────────────┐
        │ 周剧本推进 │ ──────────→ │ 选项产生效果 │
        └────────────┘                 └──────┬─────┘
              ↑                                ↓
       回到地图/对话                数值变化（好感±/压力±/黑化±）
              │                                │
        ┌─────┴──────┐                  ┌──────┴─────┐
        │  小游戏    │ ←── 胜利则好感↑ │ 状态触发   │
        │  扫雷/21点 │                  │  支线对话  │
        │  矩阵/迷宫 │                  │  信物/结局 │
        └────────────┘                  └────────────┘
```

每一周（week1 ~ week5）的主剧情对应一个 JSON 剧本文件，由 `StoryEngine` 解析驱动；玩家在地图场景中的探索行为（上课 / 自习 / 出游）触发对应的小游戏与角色支线对话；所有数值变化经由 `Player` 单例统一发出信号，UI 自动刷新。

### 1.3 角色与人设

| 角色 | 性格关键词 | 语言风格示例 | 黑化倾向 |
|---|---|---|---|
| **程设 (ProgDesign)** | 理性、冷淡、务实 | "工具的价值，是看它在谁手上" | 无 |
| **高数 (Calculus)** | 神秘、抽象、爱哲学 | "趋近，但永不到达——的爱情" | 无 |
| **线代 (LinearAlgebra)** | 阴郁、偏执、占有欲 | "我能感知到你的位置——我们之间有连续的映射" | **有，随 darkness 渐进** |
| **AI 引论 (AIIntro)** | 酷感、未来感、爱用 ML 术语 | "你是我见过最适合训练的样本" | 无 |

### 1.4 玩家可操作维度

1. **每日时段选择**：上课 / 翘课 / 自习 / 出游
2. **对话选项**：每个剧情节点 2-3 个选项，影响好感与黑化
3. **小游戏接入**：在剧情中由角色发起，由 GameManager 监听完成信号统一奖惩
4. **主攻学科**：第 3 周（期中）显式选择，决定中期支线走向
5. **信物接收**：第 4 周，好感 ≥ 50 才可领取，是结局判定的关键凭证
6. **最终选择**：第 5 周结束时决定回现实 / 留下 / 被锁定

## 第 2 章 · 剧情系统设计（成员 A 主要负责模块）

### 2.1 整体架构

剧情系统采用**数据驱动**设计：剧本完全以 JSON 描述，代码（`StoryEngine`）仅负责解析与执行。剧本作者无需懂 C++，剧情迭代不需要重新编译。

```
┌──────────────────┐    loadScript()    ┌───────────────────┐
│  *.json 剧本     │ ─────────────────→ │   StoryEngine     │
│  (14 个文件)     │                    │  • 解析 JSON     │
│                  │                    │  • 节点跳转      │
│                  │                    │  • condition 求值 │
│                  │                    │  • effects 应用  │
└──────────────────┘                    └────────┬──────────┘
                                                  │ signals
                                  nodeChanged() / effectsApplied() / scriptFinished()
                                                  ↓
                                ┌─────────────────────────────────┐
                                │   DialogWindow (UI)  ←→  Player │
                                │   显示文本/按钮         数值更新  │
                                └─────────────────────────────────┘
```

### 2.2 JSON 剧本格式（接口约定 §4）

每个剧本文件是一个对象，含 `title` / `startNode` / `nodes[]` 三个核心字段：

```json
{
  "title": "第一周·穿越异世界",
  "startNode": "intro_01",
  "nodes": [
    {
      "id": "intro_01",
      "speaker": "ProgDesign",
      "text": "终于醒了？我是程序设计……",
      "choices": [
        {
          "text": "请多关照",
          "next": "intro_02",
          "effects": [{"target": "affinity.ProgDesign", "delta": 2}],
          "condition": "darkness < 30"
        }
      ]
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 节点唯一标识 |
| `speaker` | `narrator` / `player` / 四个角色名 |
| `text` | 显示台词，支持 `\n` 换行 |
| `choices` | 选项数组；为空且无 `next` 则会 **死锁**（实测） |
| `condition` | 可选；选项级条件控制可见性，节点级条件不满足则整本结束 |
| `effects.target` | `affinity.X` / `stress` / `darkness` |
| `effects.delta` | 整数，正负皆可，自动夹紧到 `[0, 100]` |
| `next: "END"` | 触发 `scriptFinished` 信号，引擎回到地图场景 |

### 2.3 condition 表达式

引擎实现于 [src/story/StoryEngine.cpp:227-294](../src/story/StoryEngine.cpp)，支持的语法：

```
原子：  <变量> <运算符> <数字>
        例: "affinity.LinearAlgebra >= 50"
组合：  原子 && 原子 && ...      （全为真）
        原子 || 原子 || ...      （任一为真）
变量：  affinity.{ProgDesign,Calculus,LinearAlgebra,AIIntro}, stress, darkness, week, day
运算符：> >= < <= == !=
```

优先级 `||` > `&&`，靠递归字符串拆分实现，无需引入额外的表达式解析库。

### 2.5 关键设计决策

#### 2.5.1 Hub 节点 + condition 分流（角色支线对话池）

角色支线（route_*.json）设计为**分阶段对话池**：根据玩家当前好感度/黑化值，从同一个文件的不同入口加载不同等级的对话。但 `StoryEngine::loadScript` API 只接受路径不接受 `startNode`，无法在 C++ 侧做条件入口选择。

**解决方案**：每个 route 文件加一个 **hub 节点**作为 `startNode`，hub 的所有 choices 都是同样的"（继续）"文本但带不同 `condition`：

```json
{
  "id": "calculus_hub",
  "speaker": "narrator",
  "text": "（你走向高数的座位）",
  "choices": [
    {"text": "（继续）", "next": "calculus_lv1",       "condition": "affinity.Calculus < 50"},
    {"text": "（继续）", "next": "calculus_lv2_phil",  "condition": "affinity.Calculus >= 50 && affinity.Calculus < 80"},
    {"text": "（继续）", "next": "calculus_endgame",   "condition": "affinity.Calculus >= 80"}
  ]
}
```

由于 `StoryEngine::currentChoices()` 在显示前会过滤掉 condition 不满足的选项，同时只有一个按钮可见，玩家视觉上感受到的是一次普通"继续"——但实际上系统已经按当前状态把他分发到了对应阶段的对话池。**零代码改动，纯剧本侧解决。**

#### 2.5.2 节点级 vs 选项级 condition

```cpp
// 引擎对节点级 condition 失败的处理（StoryEngine.cpp:78-83）
if (!cond.isEmpty() && !evaluateCondition(cond)) {
    emit scriptFinished();   // 整本剧本立刻结束
    return;
}
```

**节点级 condition 是"硬门"**：进入节点时检查，失败直接 emit `scriptFinished`，整个剧本中止。**选项级 condition 是"软门"**：只影响该选项是否显示，不影响流程。剧本设计原则是：用选项级条件做分流，**避免在节点上挂 condition**——除非你确实想用条件失败来提前结束剧本。

#### 2.5.3 线代黑化值的多档次台词

线代是唯一具有黑化倾向的角色。剧本通过 `condition: "darkness >= X"` 在同一节点提供两套互斥台词，让相同场景在不同状态下读起来完全不同：

```json
{
  "id": "w3_la_3",
  "speaker": "LinearAlgebra",
  "text": "（凑近）一个线性变换，可以把任何空间映射到我想要的形状。\n你的脑子——也是一个空间。",
  "choices": [
    {"text": "（背脊发凉）",       "next": "w3_exam_eve", "condition": "darkness < 30",  "effects": [...]},
    {"text": "（你居然觉得有点动人）", "next": "w3_exam_eve", "condition": "darkness >= 30", "effects": [...]}
  ]
}
```

低黑化的玩家读这句台词会"背脊发凉"压力 +3，高黑化的玩家则会觉得"动人"，黑化再 +5。**同一句台词承载两条情感曲线**——这是数据驱动让剧本设计弹性最大化的样例。

## 第 3 章 · 五种结局介绍

### 3.1 结局判定优先级

由 `EndingJudge` 按下面的优先级链判定（参见 [src/story/EndingJudge.cpp](../src/story/EndingJudge.cpp)）：

```
1. 压力 ≥ 100         →  End5「陌生的天花板」
2. 黑化 ≥ 100         →  End4「永远的线代」
3. max(affinity) ≥ 80
     选择「留下」     →  End2「Best Love」
     选择「离开」     →  End3「再见」
4. 上述均不满足       →  End1「3.92」（默认）
```

### 3.2 End1 「3.92」 ——默认结局

> *"这是最常见的结局，也是最体面的告别。"*

**触发条件**：玩家通关期末考试，但没有任何角色的好感度达到 80。
**剧本**：7 节点，[ending_1_good_grade.json](../assets/scripts/ending_1_good_grade.json)
**叙事核心**：玩家回到现实，醒来时桌上是没合上的笔记本——异世界的一切像梦，但笔记里写满了她从来没学过的、却清晰得不像梦的知识。
**设计意图**：肯定"学习本身的价值"。即使没有任何浪漫线落地，玩家依然带回了知识与成长。

### 3.3 End2 「Best Love」 ——挚爱结局

> *"通道在背后悄然合上。你的现实身份会消失么？或许吧——但此刻，你已经做出了选择。"*

**触发条件**：与至少一个角色的好感度 ≥ 80，最终选择"留下"，且黑化 < 60。
**剧本**：7 节点，[ending_2_best_love.json](../assets/scripts/ending_2_best_love.json)
**叙事核心**：异世界边界开始透明，回现实的通道出现——但玩家回头看到了那个人欲言又止的身影，转身朝 ta 走去。
**设计意图**：这是浪漫线的最终承诺。玩家牺牲现实身份换取此刻的关系。

### 3.4 End3 「再见」 ——告别结局

> *"这是最难选的告别。你拥有过爱，也选择了责任——这就是成长。"*

**触发条件**：与至少一个角色的好感度 ≥ 80，但最终选择"回到现实"。
**剧本**：8 节点，[ending_3_farewell.json](../assets/scripts/ending_3_farewell.json)
**叙事核心**：玩家穿过通道，回到现实的桌前。翻开笔记最后一页，看到自己写下的不像自己字迹的话："程序的本质是表达 / 极限的本质是逼近 / 线性的本质是叠加 / 智能的本质是连接"。
**设计意图**：相较于 End2 的浪漫，End3 颂扬"舍得"。它是**最难选**也是**最成熟**的结局。

### 3.5 End4 「永远的线代」 ——黑化结局

> *"这里只有我，和你。这是最后的稳态。"*

**触发条件**：线代黑化值 ≥ 100。优先级最高。
**剧本**：5 节点，[ending_4_eternal_la.json](../assets/scripts/ending_4_eternal_la.json)
**叙事核心**：玩家醒来时不在任何熟悉的地方——四面墙写满了不断重写自身的方程式。线代说，"外面的世界太混乱，所以我把你带到一个只属于我们的子空间里"。
**设计意图**：占有欲的极致表达。这是 5 个结局里**最阴森**的，专门为黑化路线玩家保留。线代台词全部用线性代数概念隐喻情感（"子空间"、"稳态"、"不变量"），把数学的冷峻与浪漫语言折叠在一起。

### 3.6 End5 「陌生的天花板」 ——压力结局

> *"——希望你在现实中，永远不要看到这个画面。好好睡觉，好好吃饭。比分数重要的东西，还有很多。"*

**触发条件**：玩家压力值 ≥ 100。优先级仅次于 End4。
**剧本**：10 节点（5 个结局中最长），[ending_5_hospital.json](../assets/scripts/ending_5_hospital.json)
**叙事核心**：玩家在异世界精神崩溃，醒来发现自己在医院——昏迷了三天，期末考因病免考。脑中残留四个身影的最后劝告：「学习不是这样学的」「你在用消耗自己的方式换分数」「停下来吧」。
**设计意图**：这是**唯一一个对游戏内/游戏外都有警示意义**的结局。当玩家把"刷分至上"的习惯延续到游戏里，系统用一个极端结局让玩家看到这种生活方式的终点。结尾跳出剧情、直接对玩家说话，是设计上唯一一次"打破第四面墙"。

### 3.7 五结局对比

| 结局 | 触发 | 节点数 | 情感色调 | 设计立场 |
|---|---|---|---|---|
| End1 「3.92」 | 默认 | 7 | 平静、温暖 | 知识本身值得 |
| End2 「Best Love」 | 高好感 + 留下 | 7 | 浪漫、不舍 | 选择陪伴 |
| End3 「再见」 | 高好感 + 离开 | 8 | 成熟、克制 | 选择责任 |
| End4 「永远的线代」 | 高黑化 | 5 | 阴森、压抑 | 占有的代价 |
| End5 「陌生的天花板」 | 高压力 | 10 | 沉痛、警示 | 健康优先 |
