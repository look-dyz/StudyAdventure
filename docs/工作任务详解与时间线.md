# 工作任务详解与三人时间线

> 保姆级任务说明：每个工作的「做什么/为什么/怎么做」+ 三人 20 天每日时间线。

## 一、我们到底要做一个什么东西？

用一句话讲：我们要做一个 **桌面端的小游戏**（用 C++ 和 Qt 写），主角是北大信科大一女生，期末通宵晕倒后穿越到异世界，遇到拟人化的四个学科角色（程设、高数、线代、AI引论），玩家可以选择上课、自习、玩小游戏来培养与角色的好感度，最终根据玩家的选择得到不同的结局。

玩家在游戏里能做什么？大致有这些：

- **看剧情对话**（像 Galgame 一样的对话框 + 角色立绘 + 多个选项）

- **在地图上自由探索**（教学楼/图书馆/未名湖/宿舍 四个地点）

- **玩 6 个小游戏**（扫雷、21点、井字棋、矩阵运算、AI迷宫、高数答题）

- **管理数值**（每个学科角色的好感度、玩家的压力值、线代的黑化值）

- **达成 5 种结局**（学霸结局、留在异世界、回到现实、被线代囚禁、压力崩溃住院）


### 整个项目最终要交什么？

助教在 6月6日 晚上 23:59 前要收到三样东西：

- **1. 可以运行的游戏程序**（C++/Qt 写的，源代码放在 GitHub 上）

- **2. 一份 10 页以内的作业报告（PDF）**（讲清楚我们做了什么、怎么做的、有什么收获）

- **3. 一段 4 分钟以内的录屏（MP4）**（演示游戏的所有主要功能，配上语音讲解）


## 二、项目拆成 5 大模块（你必须先理解的）

这个游戏看起来复杂，但其实可以拆成 5 个相对独立的模块。**理解这 5 个模块是怎么分工的，是你看懂后面所有内容的基础**。


### 模块 1：剧情系统（成员A负责）

玩家点了 "和程设说话"，屏幕弹出对话框、显示程设头像和台词、给玩家几个选项——这一整套就是剧情系统在干活。

这个模块要做：**① 写所有的剧情对话内容**（像写小说一样，需要写大量的台词和分支选择）；**② 写一段程序**去读这些剧情文件，然后按照玩家的选择推进剧情。


### 模块 2：界面与地图（成员B负责）

玩家打开游戏看到主菜单、点 "开始游戏" 后看到一张校园地图、屏幕顶部一直显示着好感度的进度条——这些都是界面模块。

这个模块要做：**① 主菜单界面**（开始游戏/读档/设置/退出）；**② 4 张地图场景**（教学楼/图书馆/未名湖/宿舍）；**③ 顶部状态栏**（显示当前所有数值）；**④ 整合素材**（背景图、角色立绘、音乐音效）。


### 模块 3：小游戏（成员C负责）

玩家点击 "在图书馆自习" 后会进入一个小游戏窗口——这就是小游戏模块。

这个模块要做：**6 个独立的小游戏**（扫雷、21点、井字棋、矩阵运算、AI迷宫、高数答题），每个都是一个独立的小程序，玩完后告诉主程序结果（赢了或输了、得了多少分）。


### 模块 4：数值系统（成员C负责）

玩家玩完扫雷赢了，程设角色的好感度从 30 涨到 35——这种数值变化的逻辑就是数值系统。

这个模块要做：**① 记录玩家所有的数值**（4 个学科好感度、压力值、线代黑化值）；**② 提供修改这些数值的接口**（让小游戏、剧情都能调用）；**③ 存档读档**（关闭游戏后再打开，进度还在）。


### 模块 5：结局判定与主控（共同协作）

玩家玩到结局时，根据当前数值判断该播哪个结局——这是结局判定。还有一个 "调度员" 决定现在该显示主菜单、地图、还是某个小游戏——这是主控。

**成员C负责实现这两块的代码框架**，**成员A负责写 5 个结局的剧情内容**。


### 为什么这样分工？

这种分工方式有一个明确的好处：**三个人写的文件是完全不重叠的**，也就是说，成员A 改自己的文件、成员B 改自己的文件、成员C 改自己的文件，互相不会改对方的代码。这样 **三个人的工作几乎不会互相阻塞**，效率最高。

**💡 三人合作的关键：约定好接口**

虽然三人各写各的，但游戏运行时需要互相"对话"——比如成员C写的扫雷玩完后，需要告诉成员A的剧情系统"玩家赢了"，让剧情继续推进。这种"对话方式"叫做**接口约定**，我们必须在 5月14日 一天之内，三个人坐下来把所有这种"对话格式"约定好，写在一份文档里。**之后大家都按约定好的格式来，就不会出问题。**

## 四、阶段一详解（5/13—5/14）：准备和设计

在写第一行代码之前，我们需要把一些事情想清楚、说清楚。这 2 天非常关键——**在桌前讨论 1 小时，可能省下后面 10 小时的返工**。

**任务 1.1　**等待并讨论 5/11 的助教反馈**　|　5/13 全天 | 全员参与

**做什么：**助教在 5/11 给了我们 5/4 提交的设计文档反馈。先把反馈仔细读一遍，看助教提了什么建议或修改要求。

**为什么：**如果助教提了"建议增加某某功能"或"某某功能太复杂建议简化"，我们必须采纳——不然最终成绩会受影响。

**怎么做：**三个人开一次线下或线上会，每个人发表对反馈的看法，最后达成一致：哪些点要改、改成什么样。把改动记录在一份文档里。

**任务 1.2　**约定**"**接口**"**——三人合作的关键**　|　5/14 上午 | 全员同时参与

**做什么：**三个人坐一起，定义三种"约定"：**(1) 成员C写的小游戏怎么把结果告诉主程序**（比如约定：游戏结束时发出一个 finished 信号，带两个参数：分数和胜负）；**(2) 成员A写的剧情文件长什么样**（用 JSON 格式，约定每个节点要包含哪些字段）；**(3) 玩家数值（好感度等）怎么读和怎么改**（约定一个全局对象，提供 getAffinity() 和 setAffinity() 这样的接口）。

**为什么：**三个人接下来的 10 天都要按这些约定来写代码。如果某天成员A想改一下剧情文件格式，可能影响到成员C的存档系统——所以这些约定一定要事先想清楚。

**怎么做：**用腾讯文档新建一份《接口约定》文件，记录所有约定。3 小时左右搞定。讨论时建议每人提出 2-3 个**"**场景**"**，比如"玩家点击图书馆 → 弹出菜单 → 选自习 → 进入扫雷 → 玩完返回"，按这个场景走一遍，确认每一步用到的接口都讨论到了。

**💡 什么是**"**接口**"**？说人话**

接口就是**"**我和你之间的约定**"**。举个例子：成员C写好了扫雷游戏，玩家赢了之后，扫雷怎么"通知"主程序它赢了？成员C不能直接修改成员A的剧情代码，所以约定：**扫雷会大喊一声 finished(分数, 胜负)**，谁想听就来听。这就是接口。

**任务 1.3　**画一张项目结构图**　|　5/14 下午 | 成员B主导

**做什么：**画一张图，让所有人一眼看懂这个项目有哪些类、哪些类之间有关系。

**为什么：**有这张图后，每个人都清楚自己负责哪几个类、自己的类要和谁交互。后面写代码就不会迷路。

**怎么做：**用画图工具（draw.io 或 ProcessOn）画。把每个模块画成一个方块，写上类名（比如 StoryEngine、Player、MapScene），用箭头表示"调用关系"。这张图后面写报告还能直接用。

**任务 1.4　**决定项目的目录结构**　|　5/14 晚上 | 成员C主导

**做什么：**在 GitHub 上新建一个空项目，决定文件夹怎么组织。

**为什么：**事先约定每个人的代码放在哪个文件夹，就不会出现三个人改同一个文件导致冲突。

**怎么做：**我建议这样组织：

- **src/story/**  ← 成员A的代码（剧情系统）

- **src/ui/**    ← 成员B的代码（界面）

- **src/games/** ← 成员C的代码（小游戏）

- **src/core/**  ← 成员C的代码（数值、存档）

- **src/common/** ← 三人共享的基类和常量（修改前要群里说一声）

- **assets/**    ← 图片、音乐、JSON 剧本文件


## 五、阶段二详解（5/15—5/17）：搭骨架

这 3 天的目标只有一个：**5/17 晚上能跑出一个最简陋的版本**，能够：开始游戏 → 进入主菜单 → 点击"开始游戏" → 看到地图 → 点击某个地点 → 看到一个空白对话框 → 关闭对话框 → 返回主菜单。

虽然这个版本什么内容都没有，但 **整个项目的**"**骨架**"**立起来了**，三个人就可以开始往骨架里填血肉了。这是后续 10 天独立开发的前提。


### 5/15 周四

**任务 2.1　**搭建项目工程，初始化 GitHub**　|　5/15 | 成员B负责

**做什么：**在自己电脑上装好 Qt 6 + CMake，新建一个 Qt 项目，能编译运行一个空白窗口；然后把代码推到 GitHub，邀请成员A和成员C加入仓库。

**为什么：**没有项目工程，谁也开始不了。这一步必须最先做。

**怎么做：**(1) 装 Qt Creator（官网下载安装包，记得勾选 Qt 6.x 和 MinGW/MSVC 编译器）；(2) 用 Qt Creator 新建 "Qt Widgets Application" 项目，确保能编译运行；(3) 用 Git 上传到 GitHub，README 写明白"怎么编译这个项目"；(4) 邀请另外两人为 Collaborator。

**任务 2.2　**实现**"**基类**"**——MiniGame 和 Subject**　|　5/15 | 成员C负责

**做什么：**写两个基类的代码框架：MiniGame（所有小游戏的爹）和 Subject（所有学科角色的爹）。这两个类先写出来，不需要实现具体功能，只要定义好接口。

**为什么：**成员C接下来写 6 个小游戏，都要继承自 MiniGame；成员A接下来要根据 Subject 派生出四个学科角色。这两个基类是"地基"。

**怎么做：**在 src/common/ 文件夹下创建 MiniGame.h 和 Subject.h。每个文件里只声明类、声明虚函数，不写实现。写完发到群里让另外两人 review，确认没问题再 push。

**任务 2.3　**实现剧情引擎骨架**　|　5/15 | 成员A负责

**做什么：**在 src/story/ 下创建 StoryEngine 类，能读取一个简单的 JSON 文件，把里面的对话内容读出来——这一步只要做到"能读、能打印到控制台"就行，不需要 UI。

**为什么：**这是成员A接下来 10 天的所有工作的基础。先确保 JSON 能正确解析，后面再添加分支、条件等复杂功能。

**怎么做：**(1) 先手写一个最简单的 JSON 文件（包含 1 个节点、1 句台词）；(2) 用 Qt 的 QJsonDocument 类去读它；(3) 把读到的内容用 qDebug() 打印出来。能跑通就算完成。


### 5/16 周五

**任务 2.4　**搭建主窗口和场景切换框架**　|　5/16 | 成员B负责

**做什么：**搭出 QMainWindow 主窗口，里面用 QStackedWidget 实现"场景切换"——可以从主菜单切到地图、再从地图切到对话窗口。每个场景里都是空的，但切换要能正常工作。

**为什么：**这是整个游戏的"骨架"。后面所有的 UI（主菜单美化、地图绘制、对话框）都加在这个骨架上。

**怎么做：**QStackedWidget 像"翻页相册"，把不同的页面装进去，需要哪个就翻到哪个。先创建 4 个空白页：MainMenuPage / MapPage / DialogPage / MiniGamePage，每页中间放一个按钮可以跳到下一页，能跳就算完成。

**任务 2.5　**实现 GameManager 主控类**　|　5/16 | 成员C负责

**做什么：**写一个全局唯一的"调度员"类，叫 GameManager。它负责管理"现在游戏处于什么状态"、"切换到下一个状态"等。

**为什么：**三个人的模块都需要这个调度员来协调——比如成员A的剧情结束了，调度员决定接下来去地图还是去玩小游戏。

**怎么做：**GameManager 用单例模式实现（全局只有一个实例）。提供几个方法：goToMap()、goToDialog(剧情ID)、goToMiniGame(游戏类型)。每个方法就是切换 QStackedWidget 的当前页面。

**任务 2.6　**实现 DialogWindow 对话框**　|　5/16 | 成员A负责

**做什么：**做一个对话框组件，能显示头像、文本、几个选项按钮。先做样式简单的版本，后面美化交给成员B。

**为什么：**对话是游戏中最高频的交互。这个组件做好了，剧情就有地方显示了。

**怎么做：**用 QLabel 显示头像和文本，用 QPushButton 显示选项。当玩家点击某个选项时，发出一个 choiceMade(int) 信号告诉外部"玩家选了第几项"。
