## 1. 公共基类与命名空间

所有公共代码放在 `namespace SA`（Study Adventure 缩写）下。

### 1.1 MiniGame 基类（小游戏统一接口）

```cpp
class MiniGame : public QWidget {
    Q_OBJECT
public:
    virtual void start() = 0;          // 开始游戏
    virtual void reset() = 0;          // 重置游戏
    virtual MiniGameType type() const = 0;
    virtual QString displayName() const = 0;

    void setDifficulty(Difficulty d);
    Difficulty difficulty() const;

signals:
    void finished(int score, bool won);    // 游戏结束信号
    void stressOccurred(int delta);        // 中途产生压力
};
```

**6 个派生类**（成员 C 实现）：
- `MinesweeperGame`、`BlackjackGame`、`TicTacToeGame`
- `MatrixGame`、`MazeGame`、`CalculusGame`

### 1.2 Subject 基类（学科角色统一接口）

```cpp
class Subject : public QObject {
    Q_OBJECT
public:
    SubjectType type() const;
    QString name() const;
    int affinity() const;
    void changeAffinity(int delta);

    virtual void interact() = 0;
    virtual MiniGame* createGame() = 0;

signals:
    void affinityChanged(int newValue);
};
```

**4 个派生类**（成员 A 实现）：
- `ProgDesignSubject`、`CalculusSubject`
- `LinearAlgebraSubject`、`AIIntroSubject`

## 2. 数值修改的统一入口

所有数值变化（好感度、压力、黑化）**只能通过 Player 对象修改**，不能在其他地方直接维护。

```cpp
Player* player = GameManager::instance().player();
player->addAffinity(SubjectType::ProgDesign, +5);   // 程设好感 +5
player->addStress(+3);                                // 压力 +3
player->addDarkness(+5);                              // 线代黑化 +5
```

数值范围会自动夹紧到 `[0, 100]`，超出无效。
修改后自动发出对应信号（`affinityChanged` / `stressChanged` / `darknessChanged`），UI 监听信号刷新进度条。

---

## 3. 场景切换的统一入口

所有场景切换**通过 GameManager 触发**，UI 监听信号实际切换 QStackedWidget。

```cpp
GameManager::instance().requestScene(GameScene::Map);     // 切到地图
GameManager::instance().requestScene(GameScene::Dialog);  // 切到对话
```

可用场景：`MainMenu` / `Map` / `Dialog` / `MiniGame` / `Ending`。

## 4. JSON 剧本格式

剧本文件放在 `assets/scripts/` 目录下，例如：
- `week1.json` —— 第一周剧情
- `progdesign_route.json` —— 程设好感路线
- `ending_best_love.json` —— Best Love 结局

### 4.1 剧本根结构

```json
{
  "title": "第一周·穿越异世界",
  "startNode": "intro_01",
  "nodes": [
    { ... 节点 1 ... },
    { ... 节点 2 ... }
  ]
}
```

### 4.2 节点结构

```json
{
  "id": "intro_01",
  "speaker": "narrator",
  "text": "你睁开眼睛，发现自己躺在一片陌生的草地上……",
  "choices": [
    {
      "text": "环顾四周",
      "next": "intro_02",
      "effects": []
    },
    {
      "text": "继续躺着",
      "next": "intro_03",
      "effects": [
        {"target": "stress", "delta": 2}
      ]
    }
  ],
  "condition": null
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 节点唯一标识（同一剧本内不重复） |
| `speaker` | string | 说话人。可选值：`"narrator"`（旁白）、`"ProgDesign"`、`"Calculus"`、`"LinearAlgebra"`、`"AIIntro"`、`"player"`（主角） |
| `text` | string | 显示的台词 |
| `choices` | array | 选项数组，为空则自动推进到 `next` 节点 |
| `condition` | string | 可选。显示条件，如 `"affinity.LinearAlgebra >= 50"` |

### 4.3 选项结构

| 字段 | 类型 | 说明 |
|---|---|---|
| `text` | string | 选项按钮显示的文字 |
| `next` | string | 下一节点的 id。特殊值：`"END"` 表示剧本结束 |
| `effects` | array | 数值变更指令数组 |
| `condition` | string | 可选。该选项的显示条件 |

### 4.4 Effects（数值变更指令）

```json
{"target": "affinity.ProgDesign", "delta": 5}
{"target": "stress", "delta": -3}
{"target": "darkness", "delta": 10}
```

`target` 可选值：
- `affinity.<SubjectName>` —— `affinity.ProgDesign` / `affinity.Calculus` / `affinity.LinearAlgebra` / `affinity.AIIntro`
- `stress` —— 玩家压力
- `darkness` —— 线代黑化值

`delta` 为整数，正数为增加，负数为减少。

## 5. 小游戏接入流程

成员 C 实现新小游戏的标准流程：

1. 在 `src/games/XxxGame.h` 中派生 MiniGame
2. 实现 `start()`、`reset()`、`type()`、`displayName()`
3. 游戏结束时 `emit finished(score, won);`
4. **不要** 直接修改 Player 数值，由 GameManager 监听 `finished` 信号统一处理
5. 在 `CMakeLists.txt` 中添加新源文件
6. 在 `GameManager::onMiniGameFinished()` 中添加对应的奖惩规则

## 7. Git 协作

- **默认开发分支**：`develop`
- **个人分支命名**：`feature/<模块>-<功能>`，如 `feature/story-week1`、`feature/ui-map`、`feature/game-minesweeper`
- **提交信息格式**：`[模块] 简述`，如 `[story] 实现分支跳转逻辑`、`[ui] 修复地图点击响应`
- **每日 pull**：开工前先 `git pull origin develop`，避免落后太多导致冲突
- **PR 合并**：向 develop 合入时 @ 另一位成员 review，至少 1 个 approval
