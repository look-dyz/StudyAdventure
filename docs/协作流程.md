# 协作流程

> 三人团队在 20 天开发周期内的日常协作机制。

## 📅 日常节奏

### 每日同步（22:00，微信群文字）

每人在群里发：
```
【小A 5/18 同步】
今日完成：StoryEngine 分支跳转、第一周开场剧本 5 个节点
明日计划：完成第一周后续剧本约 15 个节点
阻塞：无 / 等小C 提供 Player::addStress 方法（已在 develop）
```

> 15 分钟内完成。不是会议，是异步报备。

### 每周中（周三 21:00，腾讯会议 45 分钟）

议程：
1. **每人 5 分钟**：本周进度展示 + 卡住的地方
2. **接口对齐**：讨论是否需要修改 `接口约定.md`
3. **下半周排期**：基于实际进度调整任务

### 每周末（周六 21:00，腾讯会议或线下 60 分钟）

议程：
1. **演示**：把本周完成的功能跑给队友看
2. **代码 review**：互相 review 至少 1 个本周的 PR
3. **下周规划**：基于实际进度更新时间线
4. **风险排查**：参考 `项目开发规划.docx` 第六章风险点

## 🎯 里程碑评审会（线下 90 分钟）

关键节点：
- **5/17 周六晚** — 框架搭建验收（最小示例必须跑通）
- **5/27 周二晚** — 编码完成验收（所有功能冻结）
- **5/30 周五晚** — 测试通过验收
- **6/05 周四晚** — 最终成品审片

每个里程碑会议输出：
- 验收清单（完成/未完成项）
- 下一阶段调整方案
- 写入 `CHANGELOG.md`

## 💬 沟通渠道分工

| 信息类型 | 工具 | 时效要求 |
|---|---|---|
| 紧急问题（阻塞自己工作） | 微信电话 | 立刻 |
| 一般技术问题 | 微信群文字 | 1-2 小时 |
| 代码讨论 | GitHub PR/Issue 评论 | 12 小时 |
| 决策记录 | 改对应文档并 commit | 周中/周末会议后 |
| 接口变更 | 群里通告 + 改 docs/接口约定.md | 立刻 |

## 🚨 应急预案

### 队员请假

> 谁请假谁主动说，不能让队友等着。

- **半天以内**：群里说一声即可
- **1 天以上**：必须提前安排好"备份责任人"接手紧急任务

备份责任人安排：
- 成员 A 缺席 → 成员 C 负责紧急对话框相关
- 成员 B 缺席 → 成员 A 负责紧急 UI 相关（用 placeholder）
- 成员 C 缺席 → 成员 B 负责紧急基类/数值相关

### 进度严重落后（落后 1 天以上）

立刻召开**紧急会议**：

1. 不批评、不追责，先看清楚问题
2. 分析：是任务太重？卡在某个技术问题？还是个人状态？
3. 调整方案：
   - 缩减该模块的功能（保 MVP）
   - 队友支援（如果有富余时间）
   - 推迟非关键功能到 6/6 之后的优化期
4. 把调整内容更新到时间线和 CHANGELOG

### 严重 bug 影响演示

5/30 之后发现严重 bug：

1. 立刻在 GitHub 开 Issue，标签 `[bug] P0`
2. 微信群通告，相关负责人优先修复
3. 评估：能在 6/6 前修好？还是要走"降级方案"（关闭该功能）

## 🧠 心态建议

20 天的项目是马拉松，不是短跑。

- **不要追求完美**：6/6 提交一个"完整但简陋"的版本，远好于"精致但缺东西"的版本
- **每天前 30 分钟拉队友的代码**：理解他们在做什么，避免重复工作
- **遇到 bug 给自己设 30 分钟时限**：超时就发群里求助，不要硬扛
- **晚上 23:00 后停止写代码**：困了写出来的代码 bug 多于产出
- **互相 review 时只关注代码，不评价人**：用 "这里建议改成 xxx" 而不是 "你这写得不好"
